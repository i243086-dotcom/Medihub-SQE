# Booking and cancellation input inventory

The inventory separates selectable browser values, the HTTP contract and fixture state. It uses the unchanged application source at `50554b9aefbf514bc4998aed1bedd20441f793f3`. Source line links refer to the checkout.

| Screen and control | API field and type | Frontend requirement and values | Backend validation and scope |
|---|---|---|---|
| Sign In, Username text and Password password input | POST /api/auth/login, required JSON strings `username`, `password` | Native required inputs. Typed values, no supported UI length maximum. [Controls](../../frontend/index.html#L474) | Nonempty textual values; known active account with matching password. Inactive, unknown and wrong credentials are distinct. [Handler](../../backend/routes/auth.py#L11) |
| Book Appointment, Choose a specialization cards | GET /api/patient/departments has no business field. GET /api/patient/doctors, optional query string `department` | Choice from returned active specialties, required to select a doctor. [Controls](../../frontend/js/patient.js#L86) | No nonempty unknown-value rejection. A named match filters exact specialization. Empty or omitted shows all active doctors. [Handler](../../backend/routes/patient.py#L169) |
| Book Appointment, doctor button card and Profile | GET /api/patient/available-slots query `doctor_id`; GET /api/patient/doctor/availability/{doctor_id} path; POST booking body `doctor_id` | Required selection from returned doctors. Identifier is assigned from selected record and cannot be typed here. [Controls](../../frontend/js/patient.js#L122) | Query expects ASCII digit text. Detail path has nonnegative integer routing and signed binding guard. Booking accepts signed 64-bit JSON integers and positive ASCII digit strings before looking up an active doctor. Booleans and floats are distinct from integer IDs. [Slot query](../../backend/routes/patient.py#L83) · [Booking handler](../../backend/routes/patient.py#L213) |
| Book Appointment, Appointment Date input | Required `date` query and `appointment_date` JSON strings | Native date picker uses client minimum, requires nonempty. Date availability is populated remotely. [Control](../../frontend/js/patient.js#L161) | Booking requires a parsed nonpast date using UTC+05:30, while availability lookup can inspect historical data. Seven fixture days are not a business maximum. The browser minimum and server clock may differ near a date rollover. BR-01/02. |
| Book Appointment, hourly offered slot buttons | Required `appointment_time` JSON string | Available hourly choices enabled. Occupied slots excluded from selection. Submit remains disabled until a slot is selected. [Controls](../../frontend/js/patient.js#L169) | API permits parsed minute-resolution starts in 09:00–12:59 and 15:00–18:59 and reads the prefix of a legacy range. Same-day cutoff compares the current hour, including for a minute-valued request. Configured capacity and exact doctor/patient start conflicts also apply. BR-01/02. |
| Book Appointment, Notes textarea | Optional `notes` JSON string or null | Optional editable text. No maximum is implemented here. [Control](../../frontend/js/patient.js#L190) | Text, null, missing and empty accepted. Nontext rejects. No source-supported string-length BVA. |
| My Appointments, Cancel Appointment row action and confirmation | DELETE /api/patient/appointments/{appointment_id}, required path integer | ID from selected row, no free text. UI exposes cancel only for booked and requires confirmation. [Controls](../../frontend/js/patient.js#L257) | Nonnegative route, bounded SQLite binding, own appointment, booked source only. Unknown or different owner gives 404. BR-03/04. |
| My Appointments, appointment list | Optional `status` API query string | UI loads the full patient list. No editable status field on this screen. | Raw status equality if nonempty. Unknown filter returns an empty list; omitted or empty leaves all owned rows. [Route](../../backend/routes/patient.py#L189) |
| Doctor appointments, list views | Optional `time_filter`, `status`, `date` query strings | UI chooses predefined views. Date and status query variants are also API inputs. [Request](../../frontend/js/api.js#L122) | Today, upcoming booked, completed, or fallback 30-day window. Nonempty date parses, status matches literal value, and returned rows must belong to assigned doctor. [Route](../../backend/routes/doctor.py#L107) |
| Doctor appointment row cancellation/status | Required appointment ID and `status`; optional `notes` | Row actions supply ID and a known destination. The ordinary doctor status wrapper only sends status. [Request](../../frontend/js/api.js#L128) | Assigned doctor may write booked, completed or cancelled, subject to conflict checks. No terminal-cancelled requirement is approved. API notes are optional. [Handler](../../backend/routes/doctor.py#L177) |
| Admin appointments and Reschedule | ID from row; optional `status`, `notes`, `appointment_date`, `appointment_time` | New Date date input has a client minimum; Time Slot select comes from availability. [Controls](../../frontend/js/admin.js#L277) · [Modal](../../frontend/js/admin.js#L337) | Both date and time required to reach rescheduling logic. API accepts HH:MM or HH:MM:SS and does not impose the patient booking policy. Known admin labels and notes can be sent independently by API. [Handler](../../backend/routes/admin.py#L186) |
| Doctor Set Availability | POST /api/doctor/set-slots, `slots[]` with `date`, `slot_type`, `is_available` | Inputs represent morning/evening selections over the displayed week. [Controls](../../frontend/js/doctor.js#L214) | Doctor context, nonempty slots, per-date parsing and create/update persistence. Supporting configuration used to establish booking preconditions, tested separately as a dependency. |
| Treatment and linked history | Doctor POST /api/doctor/patient-history accepts `appointment_id`, `diagnosis`, `prescription`, `visit_type`, `treatment_notes`, optional `notes`; doctor history path `patient_id` | Form uses a visit-type select, diagnosis/notes text, optional prescription, and a row-derived ID. UI constrains completion by button/form state. [Doctor form](../../frontend/js/doctor.js#L382) · [Related modal](../../frontend/index.html#L572) | The history writer requires assignment and an appointment ID, persists treatment and sets completed. It defaults optional fields and does not reject an existing source state. This is tested explicitly as a dependency. No unsupported input maximum or denied source state is assumed. [Handler](../../backend/routes/doctor.py#L246) |

Availability administration and treatment/history do affect prerequisites or readback, but are not steps of the selected patient booking or cancellation operations. The 12-operation generated contract covers patient inputs, sign-in and the directly relevant list/status operations. Dependency coverage and treatment state evidence are separate. Their full product API EP/BVA is not claimed. The ledger records the exact stimuli, observed HTTP and SQLite postconditions.

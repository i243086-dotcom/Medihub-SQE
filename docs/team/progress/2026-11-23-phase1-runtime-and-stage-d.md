### Boundary and decision evidence

- The morning open, morning close, evening open and evening close hour triplets were 08/09/10, 12/13/14, 14/15/16 and 18/19/20. The shared 14:00 point was executed once per build. The hourly list and booking results matched on all 11 distinct points.
- At UTC 03:29:59 / IST 08:59:59 the same-day 09:00 slot was visible and bookable. At UTC 03:30:00 / IST 09:00:00 / PKT 08:30:00 and one second later it was hidden and rejected. At UTC 18:45 / IST 00:15 next day / PKT 23:45 same day the original date was rejected for booking. That makes the server's IST cutoff visible independently of the UI date input minimum derived from UTC.
- With seeded availability, days 5 and 6 after the fixture date were bookable, and day 7 returned no slots and rejected booking. 20 December became bookable when availability was added to the disposable fixture. This establishes the seven-day seeded data horizon. It supplies no API upper booking-date limit.
- For BR-02 let A = patient not blacklisted, B = active doctor, C = date nonpast, D = slot available, E = no booked doctor-slot conflict, F = no booked patient-time conflict. With role, input and time valid, the partition of all 64 conceptual combinations by first false predicate is A 32, B 16, C 8, D 4, E 2 and F 1, with all true 1. P1-A03 is the all-true case. Respectively P1-A16, P1-V05, P1-D01, P1-A17, P1-A06 and P1-A07 exercise the six single-false pairs. P1-D01 supplies availability for yesterday so the date condition is the determining condition. These are conceptual MC/DC candidates. The route uses sequential guards. The full per-combination feasibility and execution table remains Stage G work.
- BR-03/04 API cases cover anonymous, wrong role, assigned owner, wrong owner, missing row, booked and nonbooked source states. The doctor and admin destination matrices exercise each known state from each known source, plus an unknown destination. Their eligibility and transition rules are role-specific.
